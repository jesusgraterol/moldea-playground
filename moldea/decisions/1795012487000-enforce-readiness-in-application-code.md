# Enforce readiness in application code

Release managers need explanations from specialists, but a model-generated conclusion must not override recorded failed checks. Compute gates in TypeScript from the release catalog and apply a fixed decision precedence after specialist review.

The change analyst identifies impact and evidence concerns. The readiness reviewer independently checks the packet and analysis and proposes next actions and customer-facing copy. Their structured outputs may add holds. They cannot promote a blocked or incomplete packet to ready_for_signoff.

This keeps the final decision stable when prose changes. Canonical readiness policy describes the executable rules, and schemas and reference checks define the boundary of accepted specialist output.
